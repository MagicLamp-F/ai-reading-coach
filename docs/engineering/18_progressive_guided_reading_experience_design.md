# 渐进式导读伴读体验设计

日期：2026-06-03

## 一句话判断

这个需求对“想看书但没有耐心看下去”的用户有明确价值。它不应该被设计成传统阅读计划，也不应该只做长摘要，而应该被设计成：

```text
低门槛进入
-> 短导读激发兴趣
-> 小段原文承接
-> 白话细化解析
-> 反馈调节明天难度
-> 慢慢把用户从看导读带到看原文
```

核心目标不是一次读很多，而是让用户每天愿意开始，并且在开始后不马上退出。

## 目标用户问题

当前用户的主要问题不是“不知道书有用”，而是：

- 打开书以后没有即时反馈；
- 原文太长，启动成本高；
- 一开始就要深读，会产生压力；
- 没有足够强的兴趣钩子；
- 今天读完和明天继续之间缺少连续性；
- 非虚构容易觉得干，小说容易忘前情；
- 看短视频能看下去，看书很难持续。

所以系统要解决的不是“总结书”，而是“设计进入书的坡度”。

## 产品定位

推荐名称：

```text
渐进式导读伴读系统
```

它由三种体验组成：

- **短导读**：像高质量读书短视频一样，用问题、冲突、现实关联把用户拉进来；
- **细化解析**：截取一小段原文，逐层拆成白话解释、关键观点、例子和用户关联；
- **追剧式伴读**：对小说、传记、历史叙事类内容，按“上一集回顾 / 今日剧情 / 人物变化 / 悬念推进”组织。

这三个体验的共同点是：先降低接受门槛，再逐步提高阅读深度。

## 为什么值得做

### 1. 它解决的是启动问题

传统阅读计划通常假设用户已经愿意读，只是需要安排时间。但低耐心用户的问题更前置：他甚至不想打开原文。

渐进式导读的价值是先给用户一个很短的进入口：

```text
先看 30 秒导读
-> 再看 3 分钟解析
-> 再读 5 分钟原文
-> 再决定要不要继续
```

这比直接要求“每天读 30 分钟”更符合真实状态。

### 2. 它能把短视频的优点转化为阅读入口

短视频读书内容的优点不是深，而是会制造进入动机：

- 先抛问题；
- 先讲冲突；
- 先给一个现实场景；
- 先让用户觉得“这和我有关”。

系统可以吸收这个优点，但不能退化成廉价鸡汤。正确方式是：

```text
用短导读提高打开率
用原文片段保留阅读
用细化解析帮助理解
用反馈决定是否加深
```

### 3. 它能让用户从“听别人讲书”过渡到“自己看书”

系统不应该默认替用户读完，而是让用户经历一个接受度阶梯：

```text
只看导读
-> 看导读 + 白话解析
-> 看解析 + 少量原文
-> 看原文 + 解析
-> 先看原文，再看解析
```

这个阶梯比“今天你必须读完第 1 章”更有效。

### 4. 它能让小说也进入系统

小说不适合默认总结代读，但适合追剧式伴读。用户读小说时需要的不是观点摘要，而是：

- 前情回顾；
- 人物关系；
- 情绪线；
- 冲突推进；
- 不剧透提示；
- 今日悬念；
- 读完后的主题复盘。

这类体验更接近“追剧”，能降低长篇小说的中途退出率。

## 第一版：低耐心启动 MVP

第一版目标：

```text
让用户每天愿意打开，并完成一个很小的阅读动作。
```

第一版不追求全书深度，不追求复杂格式解析，不追求一次性读完。它只解决“今天能不能开始”。

### 第一版支持范围

优先支持：

- 非虚构书；
- 观点型章节；
- 用户手动整理的 Markdown / TXT；
- 已经能清晰分段的书源；
- 单本书 3-7 天轻计划；
- 每天 5-15 分钟。

谨慎支持：

- 小说的已读章节回顾；
- 传记和历史叙事；
- EPUB。

第一版暂不优先支持：

- 扫描 PDF；
- 复杂排版 PDF；
- 大段技术公式；
- 自动识别所有章节结构；
- 多本书并行复杂计划；
- 完整自动深读。

### 第一版每日内容结构

每天只生成一个“阅读入口”，不要把页面做成资料堆。

推荐结构：

```text
1. 今日钩子
2. 为什么这段和你有关
3. 今日只读这一小段
4. 白话拆解
5. 关键观点 / 关键冲突
6. 一个现实连接
7. 一个读后问题
8. 明天预告
```

### 第一版导读口吻

口吻要像“认真但会拉人进入的读书短视频”，而不是论文摘要。

示例：

```text
今天先别急着读完整章。

这一段真正有意思的地方是：作者表面在讲效率，实际上是在反驳一个更隐蔽的假设。你以为自己缺时间，但他会逼你面对另一个问题：你是不是根本没有判断优先级的标准？

你今天只需要带着一个问题看下面这段：

如果只能保留一个任务，你会保留什么？
```

### 第一版交互目标

每天只要求用户做一个最小动作：

- 看完导读；
- 展开原文；
- 点“看懂了 / 没看进去 / 想继续 / 太长了”；
- 或回答一个很短的问题。

这些反馈会影响明天：

- `太长了`：减少原文长度，增加导读；
- `太浅了`：增加原文和论证拆解；
- `没兴趣`：换角度讲，或建议跳过；
- `想继续`：当天开放下一小段；
- `看懂了`：明天提高一点密度。

### 第一版成功指标

第一版不以读完几本书为第一指标，而看：

- 每日打开率；
- 导读完成率；
- 原文展开率；
- 继续阅读点击率；
- 反馈提交率；
- 连续 3 天留存；
- 用户是否从只看导读逐渐转向看原文。

## 第二版：自适应伴读与追剧式阅读

第二版目标：

```text
让系统理解用户的耐心、兴趣、理解难点和叙事偏好，动态调整每天的导读方式。
```

第二版开始从“每天一个入口”升级为“长期伴读体验”。

### 第二版能力

1. 自适应难度

系统根据反馈调整：

- 每日字数；
- 导读长度；
- 原文比例；
- 白话解释比例；
- 问题难度；
- 是否加入例子；
- 是否先讲故事再讲观点。

2. 多口吻导读

支持不同模式：

- **短视频式**：先抛冲突和现实关联；
- **私教式**：直接告诉用户今天抓什么、别纠结什么；
- **深读式**：讲结构、论证、反驳和局限；
- **追剧式**：用于小说、传记、历史叙事；
- **复盘式**：用于读完后的回顾。

3. 追剧式伴读

适合小说、传记、历史叙事。每天页面结构可以是：

```text
上一集回顾
今日登场人物
今日剧情推进
人物关系变化
情绪线索
不剧透提醒
读完后解锁解析
下一集悬念
```

关键原则：

- 默认不剧透；
- 只总结已读内容；
- 未读内容只能做悬念提示，不能揭示结果；
- 人物关系图只展示用户已读到的位置；
- 主题分析可以在读后解锁。

4. 个人化连接

第二版可以把内容和用户画像连接起来：

- 这段为什么会戳中你；
- 这段和你最近的项目有什么关系；
- 这段可能挑战了你哪个固有判断；
- 这本书适不适合继续读；
- 是否应该从伴读转为速览。

5. 阅读状态记忆

系统记录：

- 用户在哪些书上容易中断；
- 用户更吃哪种导读口吻；
- 用户能接受的每日长度；
- 用户更愿意读故事、观点还是案例；
- 用户对小说是否怕剧透；
- 用户何时适合深读，何时只适合轻导读。

这些数据进入长期画像后，可以反过来影响推荐系统。

## 追剧式阅读设计

追剧式不是把小说总结掉，而是让用户更容易续上、看下去。

### 适用内容

- 长篇小说；
- 传记；
- 历史叙事；
- 案例型商业书；
- 犯罪纪实；
- 人物群像；
- 世界观复杂的作品。

### 每日结构

```text
1. 上一集 30 秒回顾
2. 今天你要关注谁
3. 今天这一段的核心冲突
4. 原文片段
5. 读后解锁：人物变化 / 伏笔 / 情绪线
6. 下一集悬念
```

### 不剧透策略

系统需要保存每个阅读计划的进度，只允许使用已读范围内的信息生成：

- 人物关系；
- 情节回顾；
- 伏笔提示；
- 主题分析；
- 未来悬念。

未读内容不能进入 prompt，除非用户明确选择“允许剧透”。

### 追剧式示例口吻

```text
上一集你看到的是：主角已经做了一个看似理性的选择，但这个选择其实把他推到了更孤立的位置。

今天这段不要急着看情节结果，重点看两件事：

第一，他说出口的理由是什么。
第二，他没有说出口的恐惧是什么。

读完以后再回来，我们拆一下这个人物为什么开始变得不可靠。
```

## 页面设计

页面要服务“低耐心进入”，不能像后台管理系统，也不能像资料库。第一屏必须让用户立刻知道今天只需要做什么。

### 设计原则

- 移动端优先；
- 第一屏只放今日阅读动作；
- 原文和导读并列但不互相抢；
- 默认短、清楚、可继续；
- 不用大段说明文解释功能；
- 不把完整书源公开暴露；
- 所有继续、跳过、太长、想深入都要成为一键反馈；
- 小说模式必须明确当前进度和不剧透状态。

### 页面 1：首页 / 今日阅读

目标：用户打开后 5 秒内知道今天读什么。

信息结构：

```text
顶部：今天读哪本书 / 第几天
主区域：今日钩子
行动区：开始 3 分钟导读 / 直接看原文
进度：连续天数、今天预计分钟数
底部：其他阅读计划
```

核心按钮：

- 开始导读；
- 继续昨天；
- 今天太忙，只看 1 分钟；
- 换一本。

### 页面 2：每日导读页

目标：把用户从“不想看”带到“愿意读一小段”。

信息结构：

```text
今日钩子
为什么和你有关
今天只抓一个问题
原文片段入口
白话拆解
读后问题
明天预告
```

交互：

- 原文可折叠；
- 解析分段逐步展开；
- 支持“太长了 / 太浅了 / 没兴趣 / 想继续”；
- 支持一键进入下一小段；
- 读完后显示简短反馈，不弹复杂表单。

### 页面 3：原文 + 解析双栏阅读页

桌面端：

```text
左侧：今日原文
右侧：导读、拆解、问题
底部：反馈与继续
```

移动端：

```text
导读
-> 原文
-> 拆解
-> 反馈
```

设计重点：

- 原文字体要适合长读；
- 解析不要压过原文；
- 段落之间要有足够呼吸；
- 重点句可以高亮，但不要满屏标色；
- 页面底部始终能继续或反馈。

### 页面 4：追剧式阅读页

目标：让小说和叙事内容像追剧一样容易续上。

信息结构：

```text
当前进度：第几天 / 已读到哪里
不剧透状态：已开启
上一集回顾
今日看点
人物关系变化
今日原文
读后解锁解析
下一集悬念
```

特殊交互：

- “我怕剧透”开关；
- “我已经读到更后面了”进度校准；
- 人物关系只显示已读范围；
- 读后解析需要用户点“我读完了”后显示。

### 页面 5：阅读计划设置页

目标：不要让配置吓退用户。

第一版只暴露最少选项：

```text
书名
书源
每天想花多久
想读几天
导读口吻
是否怕剧透
```

推荐默认值：

- 每天 8 分钟；
- 先读 5 天；
- 口吻：轻导读；
- 小说：默认不剧透；
- 非虚构：默认导读 + 原文 + 白话解析。

### 页面 6：书籍详情 / 计划页

目标：让用户看到自己不是在面对一整本书，而是在推进一个小计划。

信息结构：

```text
当前计划状态
每日进度
已生成的导读
已完成片段
用户反馈趋势
全书复盘入口
调整计划
```

### 页面视觉风格

整体应该是安静、清晰、轻量的阅读工具，而不是营销页。

建议风格：

- 背景用接近纸张的浅色或低亮度暗色；
- 内容宽度克制，适合阅读；
- 主按钮明显但不刺眼；
- 卡片只用于每日片段、计划条目和反馈，不要层层套卡片；
- 重点色用于“开始 / 继续 / 今日钩子”，不要全站单色泛滥；
- 小说追剧页可以更有叙事感，但不能喧宾夺主。

## 数据与系统关系

这个需求可以接在现有系统之上：

```text
book_sources
-> reading_plans
-> reading_plan_days
-> reading_day_packs
-> reading_progress_events
-> profile_items / reflections
```

推荐新增概念：

- `reading_mode`: `guided`, `fast_intro`, `deep_read`, `drama`;
- `tone`: `short_video`, `coach`, `deep`, `drama`;
- `patience_level`: 用户当前耐心状态；
- `source_slice`: 当天原文片段；
- `spoiler_policy`: `avoid`, `allow`;
- `completion_signal`: `opened`, `read_source`, `finished_pack`, `continued`, `dropped`。

## 第一版和第二版边界

### 第一版必须做

- 一本书创建轻计划；
- 每天切一小段；
- 生成短导读；
- 生成白话拆解；
- 页面展示导读、原文、解析；
- 四个反馈按钮：太长了、没兴趣、刚刚好、想继续；
- 小说支持基础追剧模式和不剧透提示；
- 根据反馈微调下一天长度。

### 第一版不要做

- 全格式解析；
- 复杂 PDF；
- 自动生成完整人物关系图；
- 多模型复杂路由；
- 社交分享；
- 大而全书库；
- 完整全书深读报告。

### 第二版再做

- 动态难度；
- 多口吻切换；
- 追剧式人物关系和情绪线；
- 读后解锁深层解析；
- 长期耐心画像；
- 跨书主题连接；
- 全书复盘；
- 音频导读；
- 更复杂格式解析。

## 最终建议

这个需求值得做，而且对当前用户状态比“严肃阅读计划”更值得。

真正要做的不是：

```text
帮用户把书总结完
```

而是：

```text
每天给用户一个足够短、足够有钩子、足够容易继续的入口。
```

第一版以“低耐心启动”为目标，第二版再扩展成“自适应伴读 + 追剧式阅读”。这样既能服务非虚构的知识吸收，也能服务小说和叙事内容的持续阅读。
