# 闭环设计

## 1. 核心闭环

```text
推荐
-> 用户反馈
-> 原因采集
-> 事实入库
-> Hermes 反思
-> 画像更新
-> 下次推荐使用新画像
-> 周期性复盘
```

该闭环的目的不是只让推荐变准，而是让系统逐步建立多维用户模型。

## 2. 推荐作为假设

每本书都必须携带一个系统假设。

示例：

```text
我推荐这本书，是因为我假设：
你现在真正缺的不是更多 AI 趋势信息，而是能把 Agent 项目落地的工程化方法。
```

反馈的含义不是简单的“喜欢/不喜欢”，而是在验证这个假设是否成立。

## 3. 每日 3 本书的角色

每天 3 本书建议固定为三类：

| 位置 | 类型 | 目的 |
| --- | --- | --- |
| 第 1 本 | 画像贴合型 | 验证系统是否理解当前用户 |
| 第 2 本 | 知识缺口型 | 测试用户是否愿意补短板 |
| 第 3 本 | 探索型 | 发现潜在兴趣或认知边界 |

这能避免系统只在单一兴趣里越推越窄。

## 4. 反馈分层

### 第一层：按钮反馈

```text
喜欢 / 一般 / 不感兴趣 / 已读 / 想深入
```

按钮反馈用于快速收集方向性信号。

### 第二层：原因反馈

按钮之后按情况追问一个原因。

不感兴趣的原因示例：

```text
主题不相关
我已经懂了
太浅
太难
太理论
现在不是时候
营销感太强
```

这些原因会影响不同画像维度：

```text
主题不相关 -> 降低主题短期权重
我已经懂了 -> 更新知识背景
太浅 -> 提高难度偏好
太难 -> 记录知识缺口或降低短期难度
太理论 -> 增强偏实战偏好
现在不是时候 -> 降低短期权重，不影响长期兴趣
营销感太强 -> 更新反感信息形态
```

### 第三层：周期性反思

每 7 天由 Hermes 生成 3-5 个复盘问题，用户只需回答 1-2 个。

示例：

- 这周哪本推荐最接近你真正关心的问题？
- 哪本看似相关但你其实不想读？为什么？
- 你觉得系统这周对你的最大误解是什么？
- 如果下周只探索一个方向，你希望是什么？

## 5. 多维画像更新

画像维度包括：

- 长期兴趣。
- 短期关注。
- 知识背景。
- 知识缺口。
- 阅读偏好。
- 反感模式。
- 行动阶段。
- 能量状态。
- 探索倾向。
- 自我叙事。

每条画像都必须带：

```text
内容
类别
权重
置信度
证据数量
证据列表
更新时间
最后验证时间
```

## 6. 自迭代边界

允许自动化：

- 反馈事件入库。
- 弱画像权重更新。
- Hermes 生成长期记忆摘要。
- 每周复盘报告。

需要人审：

- 修改 Skill。
- 修改推荐策略。
- 调整权重规则。
- 修改流程。
- 删除或覆盖长期记忆。

## 7. 闭环质量指标

推荐质量只是一个指标，不是唯一目标。

建议指标：

- 每日推荐完成率。
- 反馈率。
- 原因反馈率。
- 正反馈率。
- 探索型推荐命中率。
- 每周画像准确描述数。
- 每周系统误解数。
- 每条画像平均证据数。
- 30 天画像变化可解释性。
