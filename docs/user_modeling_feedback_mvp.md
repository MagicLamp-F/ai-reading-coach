# 推荐反馈驱动的多维用户建模 MVP

## 1. 核心目标

本项目的主要目标不是单纯做一个“书籍推荐机器人”，而是用“推荐 + 反馈”作为稳定交互动作，逐步从多个角度建立一个可解释、可复盘、可迭代的个人用户模型。

书籍推荐在这里不是最终目的，而是一个认知探针：

```text
推荐 = 系统提出一个关于用户的假设
反馈 = 用户验证、修正或推翻这个假设
画像更新 = 把反馈解释成多维用户模型变化
复盘 = 帮助用户更了解自己
```

最终希望系统能回答的问题包括：

- 我长期真正关心什么？
- 我最近被什么问题牵引？
- 哪些知识缺口正在影响我的行动？
- 我偏好什么样的信息表达和学习路径？
- 我反感什么类型的信息？
- 我现在更适合探索新方向，还是补齐短板？
- 哪些主题我反复回到，说明它们可能是核心关切？
- 系统对我的理解在哪些地方准确，哪些地方误解了我？

## 2. 初期策略

初期不追求复杂问卷，也不一开始做全自动自我改造。先用低成本、低打扰的方式建立闭环。

推荐采用三层反馈：

```text
第一层：按钮反馈
第二层：原因反馈
第三层：周期性反思
```

每层承担不同任务：

- 按钮反馈负责快速判断方向是否命中。
- 原因反馈负责区分“为什么命中或没命中”。
- 周期性反思负责沉淀更深层的自我理解。

## 3. 第一层：按钮反馈

每日推荐 3 本书，每本书保留五个基础按钮：

```text
喜欢
一般
不感兴趣
已读
想深入
```

这些按钮适合回答：

- 这个主题是否值得继续？
- 这本书是否应该避免重复推荐？
- 推荐方向是否大体正确？
- 用户是否想围绕该主题拓展阅读？

按钮对画像的初步影响：

| 按钮 | 初步含义 | 画像影响 |
| --- | --- | --- |
| 喜欢 | 主题、时机或推荐理由命中 | 提升长期兴趣或当前关注权重 |
| 一般 | 方向可能对，但书、时机或表达不够好 | 轻微保留主题，等待更多证据 |
| 不感兴趣 | 主题、难度、时机或表达不匹配 | 暂不直接判定反感，需要原因反馈 |
| 已读 | 用户已有相关知识或经验 | 更新知识背景和已读库 |
| 想深入 | 用户希望围绕该主题继续探索 | 提升短期关注权重，生成后续路径 |

注意：按钮反馈只能作为弱信号。单次按钮不应直接覆盖长期画像。

## 4. 第二层：原因反馈

按钮之后可以追加一个轻量原因选择。不是每次都强制填写，而是在关键反馈时触发。

### 喜欢后的原因

可选原因：

```text
主题正好
能解决当前问题
作者/案例吸引我
方法论有用
激发新问题
难度合适
```

可解释成：

- 主题正好：增强兴趣模型。
- 能解决当前问题：增强行动阶段和知识缺口模型。
- 作者/案例吸引我：增强阅读偏好模型。
- 方法论有用：增强认知风格模型。
- 激发新问题：增强探索偏好。
- 难度合适：校准阅读难度偏好。

### 不感兴趣后的原因

可选原因：

```text
主题不相关
我已经懂了
太浅
太难
太理论
现在不是时候
营销感太强
```

可解释成：

- 主题不相关：降低该主题短期权重。
- 我已经懂了：更新知识背景，而不是加入反感主题。
- 太浅：提高难度偏好。
- 太难：降低短期难度，可能记录知识缺口。
- 太理论：增强“偏实战”阅读偏好。
- 现在不是时候：降低短期权重，不影响长期兴趣。
- 营销感太强：更新反感信息形态。

### 一般后的原因

可选原因：

```text
方向对但书不够好
主题有点远
现在不急
推荐理由没说服我
我需要更实操的材料
```

可解释成：

- 方向对但书不够好：保留主题，调整搜索和筛书标准。
- 主题有点远：降低短期权重。
- 现在不急：记录时机不匹配。
- 推荐理由没说服我：改进推荐解释能力。
- 需要更实操材料：更新阅读偏好。

## 5. 第三层：周期性反思

每天不做重问卷，但每 7 天做一次轻量复盘。Hermes 可以基于本周推荐、反馈、原因和自由文本生成 3-5 个问题，用户只需要回答其中 1-2 个。

示例问题：

- 这周哪本推荐最接近你真正关心的问题？
- 哪本看似相关但你其实不想读？为什么？
- 这周你发现自己反复被什么主题吸引？
- 有没有哪个推荐让你意识到自己的知识缺口？
- 你觉得系统这周对你的最大误解是什么？
- 如果下周只探索一个方向，你希望是什么？

这些回答比按钮反馈更适合更新深层画像：

- 自我叙事
- 阶段目标
- 隐性知识缺口
- 决策偏好
- 认知盲点
- 信息抗拒模式

## 6. 多维用户模型

初期用户模型不应只做兴趣标签，建议至少保留以下维度：

| 维度 | 说明 | 证据来源 |
| --- | --- | --- |
| 长期兴趣 | 用户持续关注的问题域 | 多次喜欢、想深入、复盘文本 |
| 短期关注 | 最近 1-2 周明显升温的话题 | 近期反馈、追问、自由文本 |
| 知识背景 | 用户已经掌握或读过的内容 | 已读、我已经懂了、用户说明书 |
| 知识缺口 | 阻碍下一步行动的薄弱点 | 想深入、太难、复盘回答 |
| 阅读偏好 | 偏实战、理论、案例、框架、教程等 | 原因反馈和推荐命中情况 |
| 反感模式 | 用户不喜欢的信息形态或主题 | 不感兴趣原因、复盘中的误解 |
| 行动阶段 | 研究期、搭建期、验证期、扩展期 | 用户说明书、近期反馈、复盘 |
| 能量状态 | 当前适合重书、短材料还是章节式阅读 | 太难、太长、现在不是时候 |
| 探索倾向 | 用户愿不愿意跳出当前主题 | 探索型推荐反馈 |
| 自我叙事 | 用户如何描述自己的目标和困惑 | 周期性反思文本 |

每条画像都应保留：

```text
category
content
confidence
weight
evidence_count
evidence
last_seen_at
updated_at
```

## 7. 推荐设计：把书当作探针

每天 3 本书不应都只是“猜你喜欢”。建议每本承担不同建模目的：

```text
第 1 本：贴合当前画像
目的：验证系统是否理解用户当前关注

第 2 本：补知识缺口
目的：测试用户是否愿意补齐行动短板

第 3 本：探索型推荐
目的：发现潜在兴趣或认知边界
```

每本推荐都应该附带系统假设：

```text
推荐这本书，是因为系统假设：
你现在不是缺更多 AI 趋势信息，而是缺能把 Agent 项目落地的工程化方法。
```

用户反馈后，系统判断这个假设是否成立。

## 8. Hermes、OpenClaw、SQLite 的角色

### SQLite：事实层

SQLite 保存不可丢失的原始证据：

- 推荐记录
- 按钮反馈
- 原因反馈
- 自由文本
- 周期性复盘回答
- 画像条目
- 运行日志
- 成本日志

SQLite 是 source of truth。

### Hermes：反思和长期记忆层

Hermes 负责把事实解释成语义记忆：

- 总结用户长期偏好
- 发现短期关注变化
- 从反馈中识别知识缺口
- 生成 USER.md / MEMORY.md
- 每 7 天生成画像复盘
- 提出 Skill 或推荐策略改进建议

Hermes 不应取代 SQLite。它生成的是“语义理解层”，可以被修正、重生成、版本化。

### OpenClaw：入口和执行层

OpenClaw 负责连接外部世界：

- Telegram channel
- 用户 session
- Skill/tool 权限
- 消息路由
- 反馈按钮和后续交互

后续可以逐步用 OpenClaw 替代当前 Python 自写 Telegram poller。

### Python 后端：编排和可靠性层

Python 后端负责稳定流程：

- 每日定时触发
- 数据库读写
- 成本和调用次数记录
- 失败日志
- 周期性任务
- 调用 Hermes / Search / OpenClaw

它不负责“聪明”，它负责“可靠”。

## 9. 初期 MVP 流程

```text
1. 每天 08:00 触发推荐任务
2. 从 SQLite 读取当前画像、最近 7 天反馈和推荐历史
3. Hermes 读取 SQLite 摘要、USER.md、MEMORY.md
4. Hermes 输出今日推荐假设和主题方向
5. 搜索工具收集候选书资料
6. 模型生成 3 本推荐
7. 每本推荐附带：
   - 推荐理由
   - 系统假设
   - 对应画像维度
   - 可能不适合的原因
   - 反馈按钮
8. 用户点击按钮
9. 系统按需要追问一个原因
10. SQLite 保存按钮、原因、上下文
11. Hermes 周期性反思并更新长期记忆
12. 每 7 天生成用户画像复盘
```

## 10. 初期验收标准

第一阶段不要只看推荐准不准，而要看是否开始形成有价值的自我理解。

7 天验收：

- 每天是否能完成 3 本推荐。
- 每本推荐是否明确说明“系统假设”。
- 用户是否能低成本完成按钮反馈。
- 至少 30% 的反馈有原因选择。
- 7 天后能生成一份多维画像复盘。
- 复盘中至少有 3 条描述让用户认为“确实说中了我”。
- 复盘中至少指出 1 个系统误解。
- SQLite 中能追溯每条画像的证据来源。

30 天验收：

- 能看出长期兴趣和短期关注的变化。
- 能发现反复出现的知识缺口。
- 能区分“不喜欢主题”和“时机不对”。
- 能总结用户偏好的阅读材料形态。
- 能生成一份比初始用户说明书更准确的用户模型。

## 11. 当前实施优先级

建议按以下顺序推进：

```text
1. 保留现有按钮反馈
2. 增加原因反馈表和原因按钮
3. 扩展 profile_items 的画像维度
4. 每条推荐增加“系统假设”
5. 增加 weekly_reflection 表
6. 每周生成 3-5 个反思问题
7. 接入 Hermes 生成 USER.md / MEMORY.md
8. 再接 OpenClaw 替代 Telegram poller
9. 最后沉淀 reading-recommendation Skill
```

## 12. 一句话定义

```text
AI 读书私教系统 =
以书籍推荐作为交互探针，
以反馈作为行为证据，
以 Hermes 作为反思与画像引擎，
以 SQLite 作为事实记忆库，
长期构建一个多维、可解释、可复盘的个人认知画像系统。
```
